# 实现复盘（AI 辅助执行记录）

最难的问题是区分“模型建议”“用户确认”“保存成功”三个事实。如果仅让模型输出 success，很容易把替代时间视为已确认，或把保存失败误报成功。本项目将确认和保存校验放在业务工具中，最终状态从工具事实推导。

实际排错：初始测试临时文件权限受限；SQLite 连接需要显式关闭，连接上下文只管理事务。已添加关闭逻辑并复跑测试。重复提交案例在首次保存失败时引用自身，导致 JSON 循环引用，已用独立副本修复。时间必须使用统一 ISO 字符串，防止相同时间被误识别为改变要求。

学到的工程原则：模型选择动作，代码维护业务约束；测试应检查越权和持久化事实，而不仅检查提示词或输出措辞；Mock 的成功不能替代真实模型证据；草稿已写入而模型后续失败时应同时保留保存事实与未完成状态。

真实验收暴露了离线测试不能发现的问题：glm-4.7-flash 曾在理由中建议替代时间，却在参数中填写已占用时间，被保存层拒绝；服务还出现超时和 1305 过载。切换到官方同样免费的 glm-4-flash-250414 后响应更快，但首批出现多个 JSON、遗漏字段及未补查就尝试保存等问题。修正方式是简化为清楚的中文工具契约、反馈格式错误并要求模型重写、保留业务层拒绝保存的约束，而不是手工改写 Trace。最终 10 组真实模型案例断言均通过，修正前记录保留供对照。

GitHub 设备授权后已成功上传 main，此前账号写权限问题已解决。后续改进：候选人亲自复验并更新个人贡献；改善模型对重试次数的描述准确性；进一步增加动态规则版本与审批身份、外部排期原子预留、任意时间区间和多素材批处理。
