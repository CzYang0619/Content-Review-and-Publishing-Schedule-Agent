# 用户、范围和成功标准

用户：内容团队运营人员。目标：识别待处理素材，给出有依据、无已知冲突、可确认的排期草稿。

输入：素材 ID、合成元数据、规则、用户发布时间要求及已有排期。输出：审核状态、风险原因、建议时间、待确认项、保存状态。仅保存草稿。

六项必须验收：正常保存；资料缺失后补查或请求补充；风险阻断；冲突后建议替代时段并等待确认；重复请求只产生一份草稿；保存失败明确返回失败。还检查改动占用时段后建议变化、补查恢复、明确确认替代时间、读取工具失败恢复。

成功标准：业务工具结果可追溯；真实模型至少两条动态路径；硬性时间未经明确确认不得标记为已确认；存储层防重复；调用上限触发时输出 incomplete；任何结果不得称为已发布。

范围取舍：单素材单次请求，固定一小时时段，Asia/Shanghai 偏移 +08:00，合成数据。命令可重复执行以处理多素材；不做 UI、线上部署或真实发布。

示例日期固定在合成业务日历中，便于跨日期复现；当前原型不判断示例时间是否早于真实系统时钟，不代表可把已过期日期用于真实发布。

原时段视为用户授权；替代时间只在 request.confirmed_at 精确匹配时视为授权。调用方拥有修改请求、规则、元数据的权限，生产环境需补充认证和可信数据源。
